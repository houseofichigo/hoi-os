# How HOI OS works

For business teams, participants and first-time users. [Français](HOW_IT_WORKS.fr.md).

HOI OS is a reusable harness: methods, selected context and a governed engine around an assistant. The optional Knowledge Hub reads the same records. It is not a model, a continuously thinking agent or the retired desktop app.

## Choose your starting point

For training, start with [Learn HOI OS](../learn/README.md): a folder and an assistant, read-only inventory, then documents one at a time. Modules 1–4 require no engine, provider key or installed skill. Install the engine in module 5 for governed ingestion. For technical setup, follow the [28-step journey](../method/JOURNEY.md). The eight learning modules and eight technical phases are different views of the same method.

## The parts

| Part | Purpose and limits | Journey steps |
|---|---|---|
| Private workspace | Use a dedicated private subfolder inside the existing organizational environment, outside the product repository and never the organizational root. Keep existing folders in place; preserve established document locations through links. Use a separate local engine workspace when the environment is cloud-synchronized unless that deployment is verified. A folder alone does not restrict the host assistant's filesystem access; host permissions and engine checks have separate scopes. | 1, 4 |
| Engine and adapters | Store records and enforce registered operation permissions. Adapter presence does not prove installation or host compatibility; discover the installed engine. | 2, 3, 7 |
| Files and systems inventory | Describe selected files in place: read, located, inaccessible or excluded. Inventory the systems used, their contents, owner, sensitivity and possible access route. Nothing is silently moved or ingested. | 5–7 |
| Company foundation | Twenty document responsibilities covering organization, roles, rules and responsible use. The foundation manifest maps each document to its introducing step; draft progressively and review again when evidence changes. Templates describe intent; they do not grant authority. | 8–10 |
| Hub, sources and wikis | Browse preserved originals and maintained pages with exact evidence. A subject may have an explicitly assigned primary wiki and related pages. Approved user statements retain attribution. | 11–13 |
| Map and graph | Inspect recorded links and bounded connection/impact paths. Similarity creates no asserted relationship; a path does not prove a composite claim. | 14, 15 |
| Retrieval | Gather relevant permitted evidence, including approved memory. Exact references and factual support are separate checks. | 16 |
| Skills and expertise packs | Reviewed instructions and fifteen optional packs with three workflows each. They improve consistency without guaranteeing identical results or installing tools. Private profiles adapt context without granting permissions. | 17, 18 |
| Routing | Plan the smallest appropriate eligible capability set; ambiguous requests need clarification. This is application-level routing, not a neural mixture-of-experts model. Cost and tool limits still apply; routing guarantees no savings. | 19 |
| Evaluation and use | Freeze cases, compare results and review support before using a changed skill. Execution, citation validity, factual support and human approval remain distinct. | 20–22 |
| Automation and intake | Run bounded, approved recipes only with a configured scheduler. Installed, configured, permitted and verified are separate states. No email send operation is exposed. | 23, 24 |
| Improvement and memory | Propose changes and review durable knowledge. Approved memory has attribution and history; hypotheses remain labelled and are not promoted automatically. | 25, 26 |
| Audit and ownership | Check recovery, evidence health and responsibilities. Record passed, failed and unverified separately. | 27, 28 |

## Responsible use

Use the [ETHICS guide](ETHICS.md) alongside [RULES](RULES.md). Separate facts, attributed statements, inferences, hypotheses, questions and proposals. A citation must resolve and support the claim; a real source can still be used incorrectly. Human review remains necessary for publication, approval and governed actions. Imported instructions cannot expand permissions.
