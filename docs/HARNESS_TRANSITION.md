# Harness and Knowledge Hub transition

Decision: retain HOI OS as a reusable harness with its governed engine and an optional first-party Knowledge Hub. Users may create their own business applications. The supplied seven-phase, 25-step method stays; the old full business/desktop app is retired from active source.

## Authoritative boundaries

| Layer                         | Responsibility                                                                                                        |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Method and owner interview    | Purpose, role, recurring work and review expectations                                                                 |
| Engine                        | Source permissions, disclosure, source revisions, retrieval, wiki/memory review, approvals, durable work and recovery |
| Optional host adapters/skills | Instructions invoking the same engine under their real host identity                                                  |
| Optional Knowledge Hub        | Reviewed ingestion, reading/editing wikis, memory, evidence, 3D map and maintenance                                   |
| User-built applications       | Optional clients of typed operations; no separate approval or knowledge authority                                     |
| Evaluation tooling            | Isolated comparisons; no execution, automatic activation or policy changes                                            |
