# Client mode

Review selected relationship context, brand/product guidelines, representative approved outputs and an active brief. Start with a small useful set rather than all history. A relationship owner and delivery specialist can contribute to one shared client context.

Ask only what remains missing:
- What does the client do and what are the engagement's objectives?
- Who supplies information, reviews work and makes decisions?
- Which source versions describe the current client, brand or product?
- What examples demonstrate acceptable work?
- What is the active assignment, expected output, editing format and deadline?
- Which prior assumptions or preferences have changed?

Create/reconcile a client overview, stakeholder roles, brand/domain context and working conventions, with a source register. Put current scope and acceptance criteria in an engagement brief. Preserve the distinction between relationship-level facts and project-specific requests. Do not treat inferred visual rules as a newly approved brandbook.

Use shared reusable capabilities with the selected client context. Do not automatically create a separate skill or full 19-document foundation for every client. A separate company foundation is appropriate only when implementing an operating system for the client's own organization.
