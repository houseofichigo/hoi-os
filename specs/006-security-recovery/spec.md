# Batch F — security evidence and recovery

The security view distinguishes current read-only workspace checks from recorded synthetic build checks and unverified live behavior. Every finding carries build identity, check version, scope and a real test timestamp or an explicit absence. No overall security score or certification is produced.

Matching build, platform and architecture are required for recorded passes. Evidence expires after seven days; future, malformed, missing, changed-build, failed-suite or zero-test records cannot pass. Exported records allow only aggregate metadata. Local raw test output is excluded from packages.

Run the existing permission, upload, exact-approval, authentication, recovery, connector and prompt-injection regressions. Rehearse backup, relocated upgrade and rollback for every supported older schema using fixtures where later tables are absent. Preserve originals, IDs, approvals, approved memory and unrelated host instructions.

The desktop must report a redacted actionable error when engine imports fail, retain startup requests during asynchronous loading, and stop cleanly. No private migration, broad ingestion, live account access, remote publication or autonomous action is authorized by synthetic verification.

Live providers, OS credential-store round trips, clean-machine platforms, real assistant sessions and the pilot are separate gates requiring appropriate environments and selected scopes.
